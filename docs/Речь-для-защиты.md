# Защита проекта CodeSense 2.0 (Кейс 3: Live Code Mutation Engine)

## Слайд 1 — Представление, 25 секунд

Наш проект — **CodeSense 2.0**, платформа интерактивных P2P-аудитов для **Tomorrow School**. Мы создали полноценную клиент-серверную систему с базой данных SQLite, ролевой авторизацией (студенты, P2P-аудиторы, преподаватели/менторы) и поддержкой проектов на **Go, Rust и JavaScript**, которая проверяет реальное понимание кода через практическое исправление ошибок.

## Слайд 2 — Проблема, 35 секунд

Сегодня студент может сдать полностью работающий проект, сгенерированный нейросетью, но не понимать, как устроена его логика. Обычный запуск автотестов проверяет только код, но не знания автора. В P2P-аудите Tomorrow School важно проверить, способен ли студент ориентироваться в собственном коде и самостоятельно находить и чинить логические сбои без подсказок ИИ.

## Слайд 3 — Решение по всем пунктам кейса, 45 секунд

1. **Приём кода и GitHub-импорт:** Аудитор загружает файлы `.go`, `.rs`, `.js` с `tests.json` или импортирует репозиторий прямо по ссылке с GitHub.
2. **Анализ структуры:** Движок `engine.js` разбирает функции, условия и циклы, строя карту логических узлов программы.
3. **Генерация 3 мутаций:** Система автоматически создаёт ровно 3 мутации на разных строках (граничные операторы, логические условия, арифметика возврата) и проверяет каждую тестами в изолированном Web Worker.
4. **Интерактивная защита 10 минут без LLM:** Студент получает изменённый проект, запускает тесты и чинит баги. Модуль **Anti-LLM Guard** фиксирует переключения вкладок и крупные вставки из буфера обмена.

## Слайд 4 — Экран аудитора, БД и роли учителей и студентов, 45 секунд

В системе реализована **база данных SQLite (`node:sqlite`)** и авторизация для трёх ролей:
- **Студент** — проходит 10-минутную защиту и фиксирует объяснения найденных багов.
- **P2P-Аудитор** — подключается к сессии по коду комнаты (например, `TS-101`) через **Server-Sent Events (SSE)**, видит скрытую карту 3 мутаций, живой код студента, сигналы Anti-LLM и отмечает в чек-листе, какие ошибки студент смог объяснить.
- **Преподаватель / Ментор** — видит дашборд всей школы, список студентов и аудиторов, статистику успешных защит и выставляет финальный вердикт в БД.

## Слайд 5 — Живая демонстрация (Go / Rust / JS), 60–90 секунд

1. Входим в систему (доступно переключение ролей «Студент / Аудитор / Учитель» в 1 клик).
2. Выбираем проект на **Go (`order.go`)** из примера кейса или импортируем репозиторий с GitHub и нажимаем **«Создать аудит (3 мутации)»**.
3. Открываем **«Экран аудитора»**: видим 3 созданные мутации (`>=` → `>`, `&&` → `||`, `+` → `-`).
4. Нажимаем **«Начать защиту (10:00)»**, запускаем тесты — видим падения на граничной доставке, скидке и итоговой сумме.
5. Исправляем 3 мутации в коде, записываем наблюдение, запускаем тесты (`6/6`) и завершаем защиту.
6. В отчёте и во вкладке **«База: Учителя и Студенты»** показываем сохранённый результат (`6/6` тестов, `3/3` мутаций) и вердикт преподавателя в БД.
