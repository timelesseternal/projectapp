# CodeSense

CodeSense — работающий прототип P2P-аудита по кейсу Live Code Mutation Engine для Tomorrow School. Студент получает три логические мутации и 10 минут, чтобы исправить код и объяснить найденные причины.

## Запуск

Откройте start.cmd и перейдите на http://127.0.0.1:4173. Нужен Node.js 18+. Сборка и npm install не нужны. Приложение также работает на статическом HTTPS-хостинге.

## Демонстрация за 3 минуты

1. Нажмите «Создать аудит». Встроенный проект расчёта заказа уже загружен.
2. Откройте «Экран аудитора» в отдельном окне на этом же устройстве.
3. Нажмите «Начать защиту». Запустите тесты, покажите ошибки на границе бесплатной доставки, в скидке и в итоговом расчёте.
4. Восстановите три изменения: delivery: > обратно на >=; discount: || обратно на &&; orderTotal: - обратно на +.
5. Запишите объяснение причины ошибки, запустите тесты и завершите защиту. Покажите отчёт и экспорт JSON.

## Загрузка собственного проекта

Выберите вместе один или несколько .js файлов и tests.json, до 1 МБ суммарно. Исходный код должен проходить все тесты. Формат tests.json показан в example/. Поддерживаются обычные JS-скрипты с функциями в общей области видимости, без модулей, зависимостей и DOM. Файлы объединяются в алфавитном порядке. Тест — JavaScript-выражение и JSON-совместимый ожидаемый результат. Асинхронные результаты поддерживаются с общим лимитом 2 секунды.

## Как работает движок

engine.js выполняет лексический разбор, пропускает комментарии и строки, считает функции, условия и циклы, находит операторы сравнения, логики и арифметики. Это ограниченный анализ токенов, не полноценный AST и не LLM. Шаблонные строки пропускаются целиком, регулярные выражения не разбираются специально.

Каждую кандидатную мутацию приложение запускает с тестами в новом Web Worker. Синтаксические ошибки и изменения, которые не нарушают ни одного теста, отбрасываются. Выбираются ровно три изменения на разных строках. Затем проверяется совместная версия. Если подходящих мутаций нет, приложение объясняет причину и не создаёт фиктивное задание.

Редактор, обратный отсчёт, автоматическое завершение по истечении 10 минут, наблюдения студента и повторные тесты формируют отчёт. Соответствие мутации исправлению оценивается по связанным тестам, а понимание оценивает аудитор в обсуждении.

## Архитектура и ограничения

Frontend: HTML, CSS, JavaScript. Выполнение: Web Worker с таймаутом. Синхронизация аудитора: BroadcastChannel, только тот же браузер и origin. Сервер server.cjs раздаёт статические файлы и не исполняет загруженный код.

Это локальный хакатонный прототип, без аккаунтов и серверного разграничения ролей. Исходники и карта мутаций находятся в памяти браузера и доступны через инструменты разработчика. Встроенных LLM-помощников нет, но внешние сервисы приложение не блокирует. Отсутствие подсказок контролирует аудитор.

Web Worker предотвращает зависание интерфейса, но не является полноценной песочницей для враждебного кода. Выполняйте только доверенные учебные проекты. Нет GitHub-импорта, Go/Rust, полноценного AST, контейнерной изоляции, долговременного хранения и работы между устройствами. Перезагрузка сбрасывает сессию. Эти возможности относятся к следующему этапу разработки.

## Проверка

node test.cjs — проверка исходного примера, трёх обнаруживаемых мутаций, совместного изменения, неизменности оригинала и исключения строк/комментариев. Команда также восстанавливает example/.

node integration-test.cjs — проверка полного сценария с эмуляцией DOM и запуском браузерного Worker-кода в Node worker_threads: подготовка, ошибки, исправление, наблюдение, отчёт 6/6 и 3/3, блокировка редактора, таймаут и валидация загрузки. Это программная проверка, не проверка браузерной вёрстки.

## Файлы

dist/ — готовое приложение и логотип. docs/ — презентация и речь для защиты. example/ — исходный проект и тесты. Все интерфейсы и материалы на русском.
